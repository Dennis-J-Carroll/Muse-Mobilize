# Etched-glass UI and responsive acceptance — 2026-09-05

## Direction

Dennis requested neo-minimalist skeuomorphism: the existing palette, the physical
weight of frosted etched glass, subtle inset shadows, and thin Inter/SF-style type.
The frontend-design skill guided a shared material system rather than independent
restyling of each tool. The existing writing-desk structure stays recognizable.

Palette anchors remain paper `#F4F3EF`, deep blue `#3F5F7D`, mist `#C6D8DE`,
sage `#CDD9CF`, sand `#EAD9C6`, and ink `#2F3B44`. Secondary ink is darker for
legibility. Semantic theme lifecycle, milestone, and revision colors are retained.

- Inter Variable is self-hosted through `@fontsource-variable/inter`, including
  real italics and script subsets. Writing requires no external font service.
- Large headings use weight 300; manuscript text uses 400; control labels use
  450. The manuscript uses generous leading and a bounded measure when expanded.
- Illuminated edges, shallow inset wells, and small cast shadows give surfaces
  thickness. Blur is restricted to the shell and layered drawers/popovers, not
  every card or theme cell.
- Shared material styling lives in `web/src/styles/materials.css`; palette,
  typography, and depth primitives live in `web/src/styles/tokens.css`.
- Drawer forms, image controls, moodboard cards, Goals, Progress, and the main
  writing shell share this treatment. Theme identities remain opaque while
  sticky, so scrolling scene marks cannot show through their labels.
- Small screens (700px and below) use a horizontally scrollable tool rail.
  Drafting panes stack whenever the workspace itself is <=650px, including
  tablets with the sidebar visible. Desktop saved arrangements are unchanged.
- Keyboard focus stays visible. Reduced-motion and reduced-transparency media
  preferences have explicit fallbacks; forced colors retain card/pane borders.

## Regressions found and fixed

Both additions in `e2e/responsive.spec.ts` were observed failing for their actual
layout defects before their respective fixes:

1. At 390px viewport width, the fixed sidebar left the workspace only **92px**
   wide. The compact rail restores full-width story tools. The test also covers
   image upload → reference save → reload and a reachable project-menu popover.
2. Even after the rail fix, the desktop split arrangement squeezed the manuscript
   to **44px**. Stacking panes at this breakpoint restores a usable manuscript;
   the regression checks width, height, and scrolling between manuscript and Muse.
   Extending it to 900px also caught a 163px manuscript; a workspace container
   query now handles this intermediate size without hiding the sidebar.

Tests use the existing isolated temporary-project runner. No story content or
provider credentials were modified by this UI pass. Interactive visual review
used the existing QA project without editing its manuscript or story entities.
